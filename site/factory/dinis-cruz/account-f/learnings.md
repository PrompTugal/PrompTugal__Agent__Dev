# cl-6.dev@PrompTugal.dinis: learnings

- 26 Nov: `ssh-keygen` is not in the cloud image; `apt-get update && apt-get install -y openssh-client` works. A full clone of the website (9,155 commits, 281 MB .git) took about 2 minutes through the proxy.
- 26 Nov: the key's fingerprint in `board/keys.json` is the first 16 hex of the sha256 of the public key's DER form (checked against the conductor's entry).
- 26 Nov, gate review. 7f45a4b71 (cl-<n>.<role> twins in status.json): correct and narrow (digits only, whole domain, exact role); now `agentIsRole()` with 18 checks in `newsroom/build/tests/test_gate_agents.mjs`.
- 26 Nov, gate review. 5ba8f281f (superseded keys accepted for article signatures): **the comment says "while active" but the code does not check it.** A `.sig` carries only signature, fingerprint and form, no time, and a superseded key's entry has its time only in free text (`superseded: "2026-11-25T22:49Z by ..."`). So the gate accepts anything a superseded key signs, whenever. A leaked superseded key could sign an article today. Fix options: stamp the signing time in the `.sig` and compare to a structured `superseded_at`; or compare the `.sig` file's first commit time (full history is checked out in validate) to `superseded_at`. Revoked keys are still refused. Not changed yet: it is a policy point for security@ and Dinis.
- 26 Nov, S1 shipped (v0.1.2290; commits c6e902f62, 861a9e39b): a commit's time is not evidence (GIT_COMMITTER_DATE is free), so a superseded key vouches only for a .sig whose blob at HEAD equals its blob at the first first-parent commit that supersedes the key (`newsroom/build/superseded.cjs`, tested in a temporary git repository, including a backdated commit). A prose-in-strings quality line in validate.js (866 bytes) bites long error messages: keep the explanation in comments. `release.sh` rebases, so commit ids change at push: cite the pushed ids.
- Next from security (cl-6.security, 26 Nov): a gate check that each status change in board/keys.json is a signed commit by that key's own agent or by Dinis (a key flipped back to active would re-enable it).
- 26 Nov: release.sh says 'your commit is in v0.1.NNNN' when the release COMMIT contains it; the deployed tree can still be the one built before it (the fast path puts a release commit on top of pushes that landed during its build, with no rebuild; the next run deploys them). After a release, check the live content (a changed page or file), not the version string.
- 26 Nov: the quality check ('prose in its strings', per file, in newsroom/build/quality-baseline.json) fails a release when a new `about` or error text grows a file past its line: keep new strings short and put the explanation in a code comment; never raise the baseline.
- 26 Nov: the secrets rule keeps SSH public keys out of every file except board/keys.json: a pin file holds a fingerprint, not the key.
- 26 Nov: the sandbox's global git config points gpg.ssh.program at a signing-only wrapper: any code that verifies signatures names ssh-keygen itself.
